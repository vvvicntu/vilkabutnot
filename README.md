# Как опубликовать портфолио через GitHub Pages

В архиве находится готовый сайт: компьютерная и мобильная версии в одном проекте. Устанавливать программы, собирать проект или оплачивать хостинг не нужно для описанного варианта с открытым репозиторием.

## 1. Распакуйте архив

Скачайте vilkabutnot-github-pages.zip на компьютер. Нажмите правой кнопкой → «Извлечь всё». Внутри должны быть index.html, style.css, script.js, папки assets и fonts, файл .nojekyll и эта инструкция.

Не загружайте ZIP как один файл: GitHub должен получить распакованные файлы с папками.

## 2. Создайте репозиторий

1. Откройте https://github.com и войдите в аккаунт или зарегистрируйтесь самостоятельно.
2. Нажмите «+» вверху → New repository.
3. Repository name: portfolio.
4. Выберите Public. При этом исходники, фото и видео будут общедоступны.
5. Включите Add README.
6. Нажмите Create repository.

## 3. Загрузите сайт

1. На вкладке Code нажмите Add file → Upload files.
2. Перетащите ВСЁ содержимое распакованного архива, включая папки assets и fonts, в область загрузки. Не перетаскивайте внешнюю папку целиком: index.html должен оказаться в корне репозитория.
3. Дождитесь загрузки всех файлов, включая три MP4.
4. Нажмите Commit changes. Если предлагается выбрать ветку, оставьте main.
5. Проверьте: index.html виден сразу на вкладке Code; внутри assets лежат фотографии, обложки и три видео; внутри fonts — Soledago.ttf.

Правильная структура:
index.html
style.css
script.js
.nojekyll
README.md
assets/
fonts/

Если .nojekyll не отобразился при распаковке, создайте его через Add file → Create new file. Имя — .nojekyll; можно оставить пустым или добавить пустую строку. Сохраните Commit changes.

## 4. Включите GitHub Pages

1. В репозитории откройте Settings → Pages в левом меню.
2. В Build and deployment выберите Source → Deploy from a branch.
3. Branch: main. Папка: / (root).
4. Нажмите Save.
5. Дождитесь публикации; она может занять до 10 минут. Обновите Settings → Pages: там появится ссылка и кнопка Visit site. Статус также можно посмотреть на вкладке Actions.

Если ваш логин на GitHub — USERNAME, а репозиторий — portfolio, адрес сайта будет:
https://USERNAME.github.io/portfolio/

USERNAME нужно заменить на ваш реальный логин GitHub, который может отличаться от ника в Instagram.

Отправляйте гостевым домам ссылку из Visit site. Адрес вида https://github.com/USERNAME/portfolio ведёт на файлы проекта, а не на сайт. Ссылку на index.html или raw-файл также отправлять не нужно.

## 5. Проверьте с телефона

Откройте ссылку github.io в Safari или Chrome. Проверьте фотографии, запуск каждого видео и кнопку Instagram. Дизайн автоматически перестраивается под ширину экрана; отдельная ссылка на мобильную версию не нужна.

Если Instagram открывает ссылку с ошибкой, попробуйте «Открыть в браузере» и вставить адрес в Safari/Chrome. Если сайт не открывается и там, сравните Wi-Fi и мобильный интернет и запишите точный текст ошибки. Доступность конкретной сети или провайдера не может гарантировать сам сайт.

## 6. Как обновлять

Заменяйте изменённые файлы через Add file → Upload files → Commit changes, сохраняя имена и структуру. GitHub Pages обновит сайт. Если видна старая версия, обновите страницу или проверьте её в приватной вкладке.

## Что включено

Все предоставленные фотографии и три видео, обложки видео, интерактивный просмотр фотографий, адаптивное оформление, локальный Soledago и информация о его источнике. Manrope и Cormorant Garamond загружаются из Google Fonts; если сервис недоступен, используются системные шрифты. Сайт не требует аккаунта ChatGPT и не зависит от Sites.

Условия сотрудничества: 1–6 февраля 2027, два гостя, 3 ночи по бартеру и 2 за свой счёт; 3 Reels, 5 сторис за поездку, 1 карусель.
